# Proxy Rules

Proxy rule lists for **Surge** (iOS/macOS) and **Clash Verge Rev** (Windows). Both clients share the same `.list` rule files under `surge/`.

![Surge](https://img.shields.io/badge/Proxy_Rules-9F1D20?logo=protonvpn&logoColor=white) [![License](https://img.shields.io/badge/license-MIT-blue)](LICENSE)

## Rule Categories

| File | Description |
|------|-------------|
| `blocked.list` | Domains requiring proxy access (social media, AI services, etc.) |
| `unblock.list` | Domestic domains routed directly |
| `openai.list` | OpenAI / ChatGPT domains |
| `claude.list` | Anthropic Claude domains |
| `google.list` | Google services |
| `netflix.list` | Netflix streaming (not wired into default rules; file kept) |
| `telegram.list` | Telegram messaging (routed to `Proxy`) |

## Quick Start

### 1. Clone

```bash
git clone https://github.com/turinglambdaai/proxy-rules.git
cd proxy-rules
```

### 2. Surge (iOS / macOS)

Reference the rule sets in your `[Rule]` section:

```ini
[Rule]
RULE-SET,https://raw.githubusercontent.com/turinglambdaai/proxy-rules/master/surge/unblock.list,DIRECT
RULE-SET,https://raw.githubusercontent.com/turinglambdaai/proxy-rules/master/surge/openai.list,OpenAI
RULE-SET,https://raw.githubusercontent.com/turinglambdaai/proxy-rules/master/surge/claude.list,Claude
RULE-SET,https://raw.githubusercontent.com/turinglambdaai/proxy-rules/master/surge/google.list,Google
RULE-SET,https://raw.githubusercontent.com/turinglambdaai/proxy-rules/master/surge/telegram.list,Proxy
RULE-SET,https://raw.githubusercontent.com/turinglambdaai/proxy-rules/master/surge/blocked.list,Proxy
GEOIP,CN,DIRECT
FINAL,Proxy
```

The `OpenAI` / `Claude` / `Google` / `Netflix` / `Telegram` policy names match the proxy groups generated by `scripts/sub.rkt`; adjust them to your own group names if you roll a config manually.

### 3. Clash Verge Rev (Windows)

Paste the contents of `scripts/clash-verge.js` into **Subscription > Global Extend Script**. It groups proxy nodes by region and configures rule-providers pointing to this repository's `surge/*.list` files. With multiple subscriptions, define them as `proxy-providers` (see [Multi-provider failover](#multi-provider-failover)).

### Subscription Conversion

Generate a full Surge configuration from one or more subscription URLs using `scripts/sub.rkt` (Racket):

1. Copy `scripts/.env.example` to `scripts/.env` and fill in your subscriptions. **Order = priority**: the first provider is primary, the rest serve as automatic fallback:
   ```
   SUB_SSRDOG_URL=https://ssrdog-subscription-url
   SUB_MITCE_URL=https://mitce-subscription-url
   ```
   The legacy single-subscription form `SURGE_SUB_URL=<url>` still works.

2. Create `scripts/surge-template.conf` with your static Surge sections (General, Rule, Host, Rewrite, MITM, etc.), using `{{PROXY_SECTION}}` as a placeholder for proxy nodes.

3. Run the converter:
   ```bash
   racket scripts/sub.rkt
   ```

   This outputs a complete Surge config to `surge/surge.conf`. A failed subscription is skipped with a warning; generation only aborts when all subscriptions fail.

**Short-lived subscription links**: some panels hand out share links that stay valid only briefly (e.g. 60s after each manual activation) instead of permanent subscription URLs. The generator handles this: the URLs in `scripts/.env` stay the same — run `racket scripts/sub.rkt` first, then activate the links in each panel; the script retries every 6s for ~90s, so the fetch lands inside the activation window automatically.

### Multi-provider failover

Both `sub.rkt` (Surge) and `clash-verge.js` (Clash Verge) build the same group structure:

| Group | Type | Members |
|-------|------|---------|
| `Proxy` | select | `Auto`, one group per provider, regions, `DIRECT` |
| `Auto` | fallback | regions — first healthy region wins |
| `SSRDOG` / `MITCE` | url-test | all nodes of that provider |
| `OpenAI` / `Claude` | select | 🇺🇸 United States default (US-blocked services), then `Proxy`, regions, `DIRECT` |
| `Google` | select | `Proxy`, regions, `DIRECT` |
| regions (🇭🇰/🇺🇸/…) | fallback | nodes ordered by provider priority |

Region groups are `fallback`: every primary-provider node is listed ahead of the backup-provider nodes, and traffic only moves to the backup when all primary nodes fail health checks (and moves back on recovery). So when ssrdog's US nodes die, mitce's US nodes take over automatically — no manual re-wiring.

**Clash Verge Rev with multiple subscriptions**: Clash Verge merges one subscription profile at a time, so put both subscriptions into the global Merge config as `proxy-providers` (use lowercase keys `ssrdog` and `mitce`; they are displayed uppercased as `SSRDOG`/`MITCE`. URLs stay in this local file, never committed):

```yaml
proxy-providers:
  ssrdog:
    url: "https://ssrdog-subscription-url"
    path: ./providers/ssrdog.yaml
    interval: 86400
    override:
      additional-prefix: "[SSRDOG] "
    health-check: { enable: true, url: "http://cp.cloudflare.com/generate_204", interval: 300 }
  mitce:
    url: "https://mitce-subscription-url"
    path: ./providers/mitce.yaml
    interval: 86400
    override:
      additional-prefix: "[MITCE] "
    health-check: { enable: true, url: "http://cp.cloudflare.com/generate_204", interval: 300 }
```

The global extend script then builds region groups across all providers via `use` + `filter`, mirroring the Surge groups.

## Project Structure

```
proxy-rules/
├── surge/               # Rule files (manually maintained)
│   ├── blocked.list     # Proxy-required domains
│   ├── unblock.list     # Direct-connect domestic domains
│   ├── openai.list      # OpenAI / ChatGPT
│   ├── claude.list      # Anthropic Claude
│   ├── google.list      # Google services
│   ├── netflix.list     # Netflix
│   └── telegram.list    # Telegram
└── scripts/
    ├── clash-verge.js         # Clash Verge Rev global extend script
    ├── sub.rkt                # Subscription-to-Surge config converter (Racket)
    ├── .env.example           # Template for subscription URLs (multi-provider)
    ├── test-sub.rkt           # Unit tests for sub.rkt
    └── test-clash-verge.mjs   # Unit tests for clash-verge.js
```

## Maintenance

Edit the `.list` files under `surge/` directly. After committing, Surge and Clash Verge will pull the updated rules on their next refresh cycle.

Run the script tests after touching `scripts/` (the region-detection patterns are shared between `sub.rkt` and `clash-verge.js` and must stay in sync):

```bash
racket scripts/test-sub.rkt
node scripts/test-clash-verge.mjs
```

## Requirements

- **Surge** or **Clash Verge Rev** as the proxy client
- **Racket** (subscription conversion with `sub.rkt`) and **Node.js** (tests)
